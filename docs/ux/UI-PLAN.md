# Local interface improvement plan

The current portable UI is a read-only overview generated by [`dashboard.py`](../../observatory/dashboard.py). It displays the last scan, project measurements, findings and an exposure summary. The CLI owns enrollment, scans and secret input. This plan improves that useful baseline without presenting future screens as shipped.

## Information structure

The primary navigation should answer five operator questions: **Overview** (what needs attention), **Projects** (what is enrolled), **Project detail** (what changed here), **Findings** (what requires a decision), and **Coverage** (what was and was not measured). Credential values do not belong to any screen. Labels, uses and exposure receipts can appear where they support a decision.

## Implementation packets

| Packet | Scenario/dependency | Work | Done conditions |
|---|---|---|---|
| UI01 — Focus the overview | O7/O9; current snapshot | Put highest-priority actionable findings before inventory; separate never-scanned, partial and old snapshots; retain exact timestamp and scope | Empty/new/partial/many-project fixtures each have one clear next action; no green all-clear for unobserved data; first meaningful section visible at 375 px width |
| UI02 — Make scope editable | O2; M01 | Preview additions/removals, show registration evidence and stable ID, distinguish selected root from discovered candidate | Keyboard user can inspect a scope diff; no action writes until explicit confirmation; removal never deletes source/secret state; concurrency failures show a retry path |
| UI03 — Project detail and history | O3/O4/O9; M02 | Addressable detail view with current Git state, metrics, snapshot comparisons and evidence references; keep unavailable fields visible as unknown | Back link preserves list position/filter; compare two real synthetic snapshots; dates/units/current-vs-historical labels visible; no data inferred from a project name |
| UI04 — Finding triage | O3/O6/O7; M04 | Filter by project/type/severity; show source scope, evidence timestamp, next action and acknowledgement expiry | A dismissed finding is visibly different from resolved; renewed evidence reopens an episode; screen-reader labels explain controls; operator-owned decisions cannot be self-approved by an agent |
| UI05 — Explain exposure coverage | O5/O6; M03/M05 | Display named slots and purposes without values; selected target labels, byte/time limits and skipped inputs; local CLI instruction for safe input | No reveal button or value in DOM/network; empty known-value set says detection unavailable; duplicate aliases and occurrence units explained; target/path disclosure stays local and deliberate |
| UI06 — Scale the table | O9; UI03/UI04 | Project search, sortable declared columns, stable sort state and grouped findings; minimize repeated counters | 200 synthetic projects remain usable at 375/768/1440 px; keyboard focus persists after sorting; every collapsed group has accessible name/state; no horizontal scrolling required for the primary task |
| UI07 — Show metrics responsibly | O7/O9; M07 | Small historical views for observed metrics; explicit units/window/source and unknown segments | Missing data never becomes zero; values from different windows are not added; charts have text/table equivalents; no animation required to interpret change |

## Validation for every packet

Use only synthetic fixtures: no customer names, actual paths, key labels or screenshots. Walk first run, no projects, one project, many projects, partial scan, unreadable state, one urgent exposure and repeated exposure. At minimum inspect 375 px and 1440 px, keyboard-only operation, visible focus, semantic headings/table headers, contrast and reduced-motion behavior. Add runtime tests for decisions/data boundaries and use a real browser for layout and interaction; source-string assertions cannot substitute for looking.

For each packet, record the scenario walked, screenshot from synthetic data, narrow/wide viewport outcome, keyboard outcome, automated checks and any unresolved defect. Stop short of provider administration until its least-privilege and confirmation model has passed a dedicated security review. Keep the public marketing site and local operational UI as separate builds.
